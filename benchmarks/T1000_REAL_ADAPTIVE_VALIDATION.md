DYN 的 push 次数比 Loc 多，原因是：相邻轮的 source vector 变化太大，复用旧状态反而需要额外“撤销旧结果”。

Loc 每轮从头计算：

p = 0
r = 当前 source

假设每轮有 10 个候选节点，那么初始 residual 主要只有当前约 10 个 source 节点。因此 Loc 只需要把当前 source 的概率质量向外传播。

DYN 保留上一轮的 p 和 r，然后更新：

r ← r + (当前 source - 上一轮 source) + 插边修正

当相邻两轮 source 支持集合几乎不重叠时：

- 上一轮约 10 个节点产生负 residual，用于撤销旧 source 的影响；
- 当前约 10 个节点产生正 residual，用于加入新 source 的影响；
- 再叠加上一轮遗留 residual；
- 如果图发生变化，还会增加插边修正 residual。

于是 DYN 初始需要处理的节点接近两个 source 集合的并集，可能从 Loc 的约 10 个变成约 20 个。

传播过程大致是：

Loc:
当前 source 正残差
→ 向外传播

DYN:
旧 source 负残差 → 撤销旧影响
当前 source 正残差 → 建立新影响
历史 residual      → 继续收敛

负残差和正残差还可能沿图传播到相同节点，先后越过阈值，使某些节点多次进入 active queue。Loc 从零开始时没有“撤销旧质量”这部分工作。

所以，DYN 只有在下面这种情况下更有优势：

相邻 source 很相似
→ source delta 很稀疏
→ 旧 p/r 大部分仍然有效
→ 只需要少量修补

而当前在线数据更接近：

相邻 source 支持几乎不重叠
→ delta 同时包含大量正负项
→ 复用价值低、撤销成本高
→ DYN push/edge visits 比 Loc 更多

早期诊断中，DYN/Loc push 比大约为：

- AmazonFashion：1.236
- Facebook：1.276
- Collab：1.706
- MovieLens：1.809
- PPA：1.838
- Vessel：1.935

引入逐轮自适应判断的原因：预测真实 DYN 和Loc的传播工作量。DYN 更便宜就继续复用，否则该轮直接走 scratch，避免为了维持旧状态而做更多 push。

一句话概括：Loc 只负责建立当前结果；DYN 既要撤销上一轮结果，又要建立当前结果。当两轮 source 差异很大时，撤销成本会让 DYN 的 push 次数超过 Loc。
